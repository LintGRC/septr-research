AI coding isn't the problem — the generators are

If AI-generated code were inherently insecure, every self-described AI-coded app would leak. We scanned the same frame, applied the same rules, and asked: does the exposure follow the generator — or the AI itself?

The headline is almost too good and it needs correcting

549 of 591 self-described AI-coded repos came back clean — 98.1% grade A. But 61% of these repos have no dependency manifest at all. They aren't apps. The headline is true; it's just not the full story.

The clean rate is partly an artifact of including non-apps. Tutorials, single-script repos, and prompt collections inflate the "clean" share. Filtering to app-shaped repos (manifest + framework + 30+ files) drops it to 71.4% — still the cleanest of the four populations, but not 92.9%.

The .env story ends here nearly absent

9 of 591 repos commit a .env file — 1.5%, a quarter of Lovable's 27.5%. The durable figure that led the Lovable report is a non-event here. Self-described AI-coded apps rarely wire backends or deploy.

But the hygiene slips persist: 38.7% have no root .gitignore — the same rate as v0 (38.2%) and nearly 4x Lovable's 10.4%. Sloppiness is general; secrets are not.

The findings are almost all false positives 82% dropped

All 45 findings across 15 repos — every one adjudicated with surrounding code. 37 were placeholders, docs examples, and test fixtures. Only 8 kept. This population ships tutorial-adjacent code with copied credentials.

82% drop rate — the highest of the three studies (Lovable 12.5%, v0 22.6%). This population ships tutorial-adjacent code with placeholder credentials. The real keeps: a format-exact 56-char Pexels API key in all four example files, and two live Supabase anon keys in client code (bounded by RLS). ogbuilds' 549-repo corpus reported 20.4% exposed-secret findings — raw rule output. Our verified read of the same population is ~1%.

Blast radius consequence, not prevalence

98.3% of repos carry nothing beyond hygiene at worst — versus 66.4% (Lovable) and 81.1% (v0).

The tier-A count (7, rule output) collapses after verification: a handful of repos with real data-access credentials, none of it in a frontend bundle.

The app-shaped correction

The self-described frame includes a lot of repos that aren't apps: 61% have no dependency manifest, and the median repo is 17 files / 119 KB. Filtering to app-shaped repos — a manifest, a framework, ≥ 30 files — gives the fair baseline for "AI-built apps without a generator signal" (N=91, median 107 files / 2.9 MB — comparable to the generator populations).

Four populations, one engine

Same rules, same adjudication standard, four populations — the comparison chart tells the whole corpus program's story.

The exposure tracks how much real app wiring exists, and the leak mechanics follow the generator: Lovable apps leak through .env (27.5%), v0 apps through hardcoded code keys (15.4% tier A), and even app-shaped AI-coded repos leak far less (7.7% env, 4.4% tier A) — with the best hygiene of the four.

The conclusion is clear

The evidence across all four populations says the same thing: exposure follows the generator, not the model. Lovable leaks through .env (27.5%). v0 leaks through code (15.4% tier A). The self-described AI-coded population leaks at 1.5% unfiltered, 7.7% app-shaped. That gap — 27.5% down to 1.5% — is the generator, not the AI.

Methodology

Signal: self-description. topic:ai-generated (repo search, 898 — the complete enumerable surface) merged with "vibe-coded" filename:README.md (top best-match), deduplicated to a 1,000-repo frame; fixed-seed sample of 600 (seed 20260812), 591 downloaded (9 exceeded the 150 MB cap).

Scan: the same Septr rules engine as the Lovable and v0 studies, offline, over each repo's GitHub tarball.

Verification: all 45 findings across all 15 affected repos — exhaustive, no subsample — adjudicated with surrounding code under the only-high-confidence-drops-count rule. 37 dropped (82%), 8 kept.

Signal honesty: 27.1% of scanned repos carry a README text marker; the rest are topic-identified (ai-generated), which the tarball cannot confirm. The frame is "topic OR README self-description" — exactly what "describes itself as AI-coded" means.

Ethics: aggregates and anonymized rows only; no repo-to-credential mapping; no confirmed-live testing.
